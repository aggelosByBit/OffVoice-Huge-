OFFVOICE AI — ΕΝΙΑΙΑ ΔΟΚΙΜΑΣΤΙΚΗ ΕΚΔΟΣΗ
Ημερομηνία: 12 Νοεμβρίου 2026

Το πακέτο περιλαμβάνει ολόκληρη την εφαρμογή και τα tests. Χρειάζονται ΟΛΑ τα αρχεία,
όχι μόνο αντικατάσταση των τεσσάρων αρχικών. Δεν περιλαμβάνει πραγματικά credentials.
Δεν έχει εγκατασταθεί στο Render και δεν έχουν σταλεί πραγματικά email ή SMS.

ΠΡΟΤΕΙΝΟΜΕΝΗ ΣΕΙΡΑ

1. Κρατήστε την τωρινή έκδοση σε ξεχωριστό Git commit/branch για επιστροφή.
2. Βάλτε το περιεχόμενο αυτού του φακέλου σε νέο δοκιμαστικό branch.
3. Εκτελέστε τα tests και το τοπικό demo.
4. Συνδέστε ξεχωριστό δοκιμαστικό Google Calendar στο Render staging.
5. Επαληθεύστε εκεί Google, Groq, email και τις περιπτώσεις του MANUAL_CHECKS.txt.
6. Μετά από επιτυχή έλεγχο αποφασίζετε τη μετάβαση της υπάρχουσας εγκατάστασης.

ΤΟΠΙΚΗ ΕΚΤΕΛΕΣΗ — PYTHON 3.12

Ανοίξτε terminal μέσα στον φάκελο του πακέτου. Εκτελέστε κάθε εντολή χωριστά:

  python -m venv .venv
  .venv/bin/python -m pip install -r requirements-dev.txt
  .venv/bin/python -m pytest -q

Σε Windows τα εκτελέσιμα είναι .venv\Scripts\python.exe αντί για .venv/bin/python.

Αντιγράψτε το .env.example ως .env με τον file manager. Οι προεπιλογές είναι για demo:
  DEMO_MODE=true
  COOKIE_SECURE=false
  PUBLIC_ORIGIN=http://127.0.0.1:8000

Έπειτα:
  .venv/bin/python -m uvicorn main:app --env-file .env --host 127.0.0.1 --port 8000 --workers 1 --no-access-log

Ανοίξτε http://127.0.0.1:8000.
Το demo ελέγχει σελίδα, επικοινωνία, ξεχωριστές συνεδρίες και διαγραφή.
Χρησιμοποιεί εικονικές υπηρεσίες: ο demo βοηθός δεν κάνει πραγματική συνομιλιακή κράτηση.
Οι πλήρεις ροές κρατήσεων καλύπτονται από tests και κατόπιν από staging με πραγματικούς providers.

RENDER STAGING

Χρησιμοποιήστε ένα Web Service ανά ιατρείο, έναν worker και μία instance.
Το service πρέπει να μένει ενεργό για callbacks και νυχτερινές εργασίες.
Sleeping/free services δεν παρέχουν αξιόπιστη εκτέλεση στις 22:00.

Build Command:
  pip install -r requirements.txt

Start Command:
  uvicorn main:app --host 0.0.0.0 --port $PORT --workers 1 --no-access-log

Health Check Path:
  /health

Βάλτε στο Environment του Render:
  DEMO_MODE=false
  COOKIE_SECURE=true
  PUBLIC_ORIGIN=https://το-staging-service.onrender.com
  SESSION_SECRET=ξεχωριστό τυχαίο μυστικό τουλάχιστον 32 χαρακτήρων
  CALENDAR_ID=το αναγνωριστικό του δοκιμαστικού ημερολογίου
  GOOGLE_CREDENTIALS_JSON=το πλήρες JSON του service account
  GROQ_API_KEY=το κλειδί σας
  GROQ_MODEL=ενεργό μοντέλο με tool calling στον λογαριασμό σας
  RESEND_API_KEY=το κλειδί σας
  DOCTOR_NOTIFICATION_EMAIL=το δοκιμαστικό email παραλήπτη
  EMAIL_FROM=επιβεβαιωμένος αποστολέας/domain στον Resend
  PRIVACY_NOTICE=ακριβής ενημέρωση δοκιμαστικού ιατρείου, με χρήση μόνο εικονικών στοιχείων

Για δημιουργία SESSION_SECRET τοπικά:
  python -c "import secrets; print(secrets.token_urlsafe(48))"
Εισάγετέ το στο Render. Μην το βάλετε σε Git ή σε μήνυμα συνομιλίας.

Το service account χρειάζεται δικαίωμα επεξεργασίας στο συγκεκριμένο Calendar.
Το παλιό GOOGLE_CREDENTIALS υποστηρίζεται ως alias· προτιμήστε GOOGLE_CREDENTIALS_JSON.
Το παλιό model ID διατηρείται ως default, αλλά η διαθεσιμότητά του θέλει έλεγχο στον Groq.
Ο αποστολέας onboarding@resend.dev δεν χρησιμοποιείται ως production default.

Τα όρια αιτημάτων βασίζονται στο request.client.host. Πριν την κανονική χρήση,
ελέγξτε την πραγματική IP πίσω από το Render proxy και ρυθμίστε μόνο τους έμπιστους
proxies του Uvicorn. Μην εμπιστεύεστε αυθαίρετο X-Forwarded-For από το διαδίκτυο.

ΣΥΝΟΜΙΛΙΕΣ ΚΑΙ ΗΜΙΤΕΛΗ ΑΙΤΗΜΑΤΑ

- Κάθε επισκέπτης έχει τυχαίο session cookie, HttpOnly και SameSite=Lax.
- Τα μηνύματα παραμένουν μόνο στη RAM, για περίπου 30 λεπτά αδράνειας από προεπιλογή.
- Η ανανέωση/το κλείσιμο σελίδας δεν ανακτά ούτε εγγυάται άμεση διαγραφή στον server.
- Η «Διαγραφή συνομιλίας» αφαιρεί τη συγκεκριμένη συνομιλία και εκκρεμή επανάκληση.
- Δεν δημιουργείται τοπική βάση με συνομιλίες, ονόματα ή τηλέφωνα.
- Η επανάκληση απαιτεί τη σχετική επιλογή του επισκέπτη και στοιχεία που έδωσε ο ίδιος.
- Μετά από περίπου 15 λεπτά αδράνειας, στέλνεται email με όνομα/τηλέφωνο στη γραμματεία.
- Επιτυχής ολοκλήρωση καθαρίζει τα προσωρινά στοιχεία επανάκλησης.
- Μετά από αποστολή ή λήξη καθαρίζονται τα στοιχεία επανάκλησης από τη RAM.

ΣΗΜΑΝΤΙΚΟ: επανεκκίνηση/deploy διαγράφει τη RAM. Ένα ημιτελές αίτημα μπορεί τότε
να χαθεί πριν σταλεί email. Αυτό είναι το όριο της επιλογής χωρίς μόνιμη αποθήκευση
στοιχείων ημιτελών αιτημάτων. Απόλυτη εγγύηση ανάκτησης θα απαιτούσε προσωρινή
ανθεκτική αποθήκευση και ξεχωριστή συμφωνία για σκοπό/χρόνο διατήρησης.

ΠΩΣ ΑΛΛΑΖΟΥΝ ΤΑ ΡΑΝΤΕΒΟΥ

- Δημιουργία και μεταφορά ελέγχουν διαθεσιμότητα ξανά στο κοινό Google Calendar.
- Ελέγχονται και συμβάντα της γραμματείας, καθώς και ολοήμερα κλεισίματα.
- Η διάρκεια προκύπτει από APPOINTMENT_MINUTES, όχι από απόφαση του AI.
- Πρόσβαση γίνεται με πλήρη κωδικό έξι χαρακτήρων. Η ανάκτηση με σκέτο τηλέφωνο αφαιρείται.
- Σε χαμένο κωδικό ο ασθενής παραπέμπεται στη γραμματεία.
- Υπάρχει περιορισμός προσπαθειών και έλεγχος μοναδικότητας νέου κωδικού.
- Αναγνωρίζονται παλιές κρατήσεις με την αρχική σήμανση OffVoice AI και ακριβή κωδικό.
- Η ακύρωση αφήνει διαφανή/μη δεσμευτική ένδειξη στο Calendar για στατιστικά.
  Αφαιρούνται όνομα, τηλέφωνο και λόγος επίσκεψης από αυτήν την καταχώρηση.
- Ο κωδικός και τα τεχνικά στοιχεία ακύρωσης παραμένουν στο Calendar και εξακολουθούν
  να χρειάζονται προστασία. Δεν θεωρούνται αυτομάτως ανώνυμα δεδομένα.

Η Google Calendar API δεν δίνει συναλλαγή «έλεγχος όλων των slots και κράτηση» μαζί
με τις ανεξάρτητες εγγραφές της γραμματείας. Ο lock προστατεύει τις ενέργειες αυτής
της μίας εφαρμογής. Ταυτόχρονη εξωτερική εγγραφή ανάμεσα σε έλεγχο και αποθήκευση
παραμένει τεχνικό όριο. Δεν τεκμηριώνεται υπόσχεση «μηδενικές διπλοκρατήσεις».

EMAIL

Οι επιτυχείς κρατήσεις, μεταφορές και ακυρώσεις καταγράφουν εκκρεμή ειδοποίηση στο
Calendar. Η αποστολή επιχειρείται αμέσως και επαναλαμβάνεται περιοδικά σε αποτυχία.
Το ίδιο κλειδί Resend αποτρέπει επανάληψη μέσα στο παράθυρο idempotency του παρόχου.
Μετά από 23 ώρες η εκκρεμότητα σημειώνεται για χειροκίνητο έλεγχο πριν από νέα αποστολή.

Τα email κρατήσεων έχουν τύπο ενέργειας, κωδικό, ώρα και σύνδεσμο στο Calendar του
ιατρείου. Τα πλήρη στοιχεία ασθενούς παραμένουν εκεί. Αυτό μειώνει τη διακίνησή τους
και κρατά σταθερό το περιεχόμενο στις επαναλήψεις. Τα email ημιτελών αιτημάτων
περιέχουν όνομα και τηλέφωνο, όπως απαιτεί η επανάκληση.

ΥΠΕΝΘΥΜΙΣΕΙΣ ΑΣΘΕΝΩΝ — ΑΠΕΝΕΡΓΟΠΟΙΗΜΕΝΕΣ

Ο προγραμματισμός είναι στις 22:00 Europe/Athens για την επόμενη ημέρα.
Γίνεται επανέλεγχος ανά λεπτό μετά τις 22:00 και περιλαμβάνονται νέες κρατήσεις
που μπαίνουν αργότερα το ίδιο βράδυ. Μια μεταφορά επιτρέπει ενημερωμένη υπενθύμιση.

Έχει προετοιμαστεί προσαρμογέας Twilio SMS ως διαθέσιμη επιλογή, χωρίς ενεργοποίηση.
Δεν έχουν υλοποιηθεί Viber/WhatsApp integrations. Η επιλογή provider παραμένει ανοικτή.
Για χρήση Twilio απαιτούνται εγκεκριμένος αποστολέας, ενεργός λογαριασμός, έλεγχος
επιτρεπτής επικοινωνίας και οι σχετικές μεταβλητές. Μόνο τότε:
  SMS_PROVIDER=twilio
  REMINDERS_ENABLED=true

Δεν υπάρχει ακόμη callback παράδοσης παρόχου: «sent» σημαίνει αποδοχή του API,
όχι αποδεδειγμένη παράδοση στο κινητό. Άγνωστη έκβαση δεν επαναλαμβάνεται αυτόματα.
Αποστέλλονται υπενθυμίσεις μόνο για αναγνωρισμένες κρατήσεις OffVoice με τηλέφωνο.
Τα χειροκίνητα ραντεβού δεσμεύουν διαθεσιμότητα, αλλά δεν λαμβάνουν αυτόματα SMS.

ΑΝΑΦΟΡΕΣ ΚΑΙ ΚΑΤΑΓΡΑΦΗ ΠΡΟΣΕΛΕΥΣΗΣ

Προεπισκόπηση του προηγούμενου ημερολογιακού μήνα, χωρίς αποστολή:
  python monthly_report.py

Συγκεκριμένος μήνας:
  python monthly_report.py --month 2026-11

Πραγματική αποστολή στον ορισμένο γιατρό:
  python monthly_report.py --month 2026-11 --send

Αν υπάρχει ήδη Render Cron Job για την αναφορά, ενημερώστε την εντολή του ώστε
να περιλαμβάνει --send. Δεν δημιουργήθηκε νέο εξωτερικό Cron Job από το πακέτο.

Η πραγματική προσέλευση καταγράφεται από εξουσιοδοτημένο χειριστή, μετά τη λήξη:
  python manage_appointment.py --code ABC123 --attendance attended --apply
ή --attendance no_show / unknown.
Η λειτουργία δεν εκτίθεται στο chat ή σε δημόσιο admin endpoint.

Έλεγχος πλήθους εκκρεμών/αβέβαιων ειδοποιήσεων χωρίς στοιχεία ασθενών:
  python ops_status.py

BILLING_BASIS=unset σημαίνει ότι δεν υπολογίζεται χρεώσιμο πλήθος.
created/confirmed/attended ενεργοποιούν μόνο αντίστοιχη εκτίμηση στην αναφορά.
Οι μεταφορές δεν δημιουργούν νέα καταχώρηση. Οι ακυρωμένες κρατήσεις εξαιρούνται
από τις εκτιμήσεις χρεώσιμων. Δεν υπάρχει σύνδεση με πληρωμές ή αυτόματη χρέωση.

ΠΡΙΝ ΑΠΟ ΠΡΑΓΜΑΤΙΚΟΥΣ ΑΣΘΕΝΕΙΣ

Χρειάζεται έλεγχος της ενημέρωσης απορρήτου, των συμβάσεων επεξεργασίας, των χρόνων
διατήρησης σε Calendar/email/providers και των ρυθμίσεων λογαριασμών. Το πακέτο δεν
πιστοποιεί GDPR. Οι ιατρικοί περιορισμοί είναι διοικητικά guardrails και δεν αποτελούν
κλινικό σύστημα αναγνώρισης επειγόντων.

Η σελίδα λειτουργεί στο ίδιο origin με το API. Cross-origin widget/iframe χρειάζεται
ξεχωριστή ασφαλή ενσωμάτωση: η τρέχουσα CSP επιτρέπει iframe μόνο στο ίδιο origin.
